# OpenAI 账号额度周期预测：功能实施要求

> 状态：已实施。

## 1. 需要实现

### 支持范围

- 仅支持 OpenAI OAuth 的 Plus、Team、Pro 主额度周窗口。
- 一个周期一条记录，保存使用金额、Token 量、调用次数、使用比例和一个预测额度。
- 周期内没有使用，不创建历史记录。
- 支持普通 API 请求和流式请求，不依赖管理页面打开。

### 触发入口

两个入口共用本地窗口统计和记录保存方法：

1. 用户通过 sub2api 调用模型，实际用量成功入库后触发；按账号节流 30 秒。
2. 后端组装账号用量窗口时触发，覆盖单账号和批量查询路径。

首次满足条件直接执行，后续 API 触发距上次执行不足 30 秒则跳过。下一次执行重新统计整个周期的累计用量，不只统计最新一笔。

API 入库入口只读取已有比例缓存，不主动查询上游。提取共用本地逻辑，不直接调用可能发起上游探测的完整 `getOpenAIUsage`。

### 使用金额和预测

复用账号用量窗口的数据口径：

| 数据 | 字段 |
| --- | --- |
| 使用金额 | `SevenDay.WindowStats.Cost` |
| 使用 Token 量 | `SevenDay.WindowStats.Tokens` |
| 使用请求数 | `SevenDay.WindowStats.Requests` |
| 使用比例，单位 0～100 | `SevenDay.Utilization` |
| 预计重置时间 | `SevenDay.ResetsAt` |

使用比例严格超过 5% 时计算：

```text
预测额度 = 最新使用金额 × 100 / 最新使用比例
```

- 比例小于或等于 5%：照常记录使用情况，预测为 null。
- 有请求但金额为 0：仍记录使用，暂不输出预测。
- 每次用最新金额和比例重新计算，直接覆盖旧预测，无论新值变大还是变小。
- 当前比例回到 5% 或以下时，清空当前记录的预测；已结束记录不变。
- 金额采用账号口径 `Cost`，不使用用户扣费 `UserCost`。

### 周期切换

提前重置判断：

```text
上次快照使用比例 - 当前使用比例 > 2
```

回落超过 2 个百分点才切换，恰好回落 2 个百分点不切换。手动、自动和 OpenAI 外部提前重置统一通过刷新后的主周窗口数据识别。

自然重置判断：旧窗口已到期，且有效上游数据给出新的未来重置时间时，进入新周期。

统计起点：

- 首次接入：沿用当前窗口默认起点。
- 普通自然重置：窗口连续时，以此前已知的到期时间作为新起点。
- 检测到提前重置：以发现这次重置的时间作为新起点。
- 后续统计：沿用已保存起点，不每次重新用预计重置时间减七天。

将起点传给 `GetAccountWindowStats`，结果同时用于页面周窗口和周期记录，防止提前重置后混入旧起点之前的用量。

切换时只补充旧记录的结束时间，保留其最后保存的金额、比例和预测。保存新起点后，只有发现新周期使用才创建新记录。只变化 5h 不切换周记录。

### 数据存储

新增 `openai_quota_periods`：

| 字段 | 说明 |
| --- | --- |
| `id` | 独立主键 |
| `account_id` | 账号 ID |
| `started_at` | 统计起点 |
| `ended_at` | 结束时间，当前周期为空 |
| `reset_at` | 上游预计重置时间 |
| `request_count` | 使用请求数 |
| `token_count` | 总 Token 量（输入、输出、缓存创建、缓存读取之和） |
| `used_usd` | 账号成本 |
| `used_percent` | 使用比例 |
| `predicted_quota_usd` | 预测值，可为空 |
| `snapshot_at` | 本次统计时间 |
| `created_at` / `updated_at` | 创建和更新时间 |

金额使用 NUMERIC。`(account_id, started_at)` 唯一，每账号最多一条 `ended_at IS NULL` 的记录。预计重置时间不作为唯一键。

在 `accounts.extra.openai_quota_period` 保存当前起点、预计重置时间、上次有效比例和对应快照时间，用于重置后尚无使用的状态。不新增第二张状态表，只合并本功能的键。

### 写入要求

- 读取有效周窗口快照，判断周期，确定起点，再一次性统计金额、Token 量和调用次数并保存。
- 有使用则创建或覆盖当前记录，不通过累加回调金额更新记录。
- 账号状态和周期记录使用短事务，按账号串行更新，重复触发不重复建档。
- 实施时新增 Schema、迁移和 Repository，接入共用统计服务及两个触发入口。
- 上线时同步 README，说明支持范围、触发方式、节流、预测及重置规则。

### 账号列表中的预测值

- 查询账号管理列表时，后端从 `openai_quota_periods` 批量读取本页账号当前周期的 `predicted_quota_usd`，随账号列表返回，不逐账号单独查询。
- 当前周期取 `ended_at IS NULL` 的记录；没有当前记录或预测为空时返回 null，不拿已结束周期的旧预测替代当前值。
- 在账号列表“用量窗口”单元格的最下方新增一行 `预测额度：$金额`，沿用现有金额格式。
- 仅当预测值存在且不为 0 时显示；为空或为 0 时整行隐藏，不占用空白行。只对本功能支持的账号展示。
- 前端直接展示列表返回的已保存值，不计算预测，不为每行发起额外预测请求。
- 列表读取不触发预测重算或上游额度查询；预测更新仍由 API 用量入库和窗口组装两个入口负责。

### 操作按钮与历史弹窗

- 在支持账号的操作列新增“额度历史”图标按钮，复用现有图标组件并提供悬停提示。
- 点击按钮打开该账号的独立额度历史弹窗，标题包含账号名称；复用现有弹窗组件。
- 弹窗打开时调用管理端只读历史接口，直接查询 `openai_quota_periods`。不从使用明细重新统计，不重新计算预测。
- 使用分组柱状图：每个周期一组，两根并排柱分别展示 `used_usd`（使用量）和 `predicted_quota_usd`（预测量）。
- 横轴为独立周期类别，按开始时间从早到晚排列，同时标注周期开始和结束时间，精确到小时；当前周期优先使用 `reset_at` 作为结束时间，无可用时间时标注“进行中”。纵轴为美元金额，从 0 开始，两个系列共用刻度。
- 两个系列使用不同颜色及图例；悬停或触摸展示该周期起止时间、使用金额、预测金额、Token 量和调用次数。
- 默认展示最近 20 个周期，分页查看更早历史；每页按时间正序绘图，同日多个周期保留为独立分组，详细提示包含时间。
- 预测为 null 时不绘制该周期的预测柱，提示“暂无预测”，不能将 null 转成 0；真实零值按 0 展示。没有预测的周期仍保留使用量柱。
- 提供加载、无历史记录和查询失败状态，失败时支持重试；关闭或切换账号时不能串用上一账号的数据。
- 复用项目已有 Chart.js / vue-chartjs，不新增图表依赖，不增加折线/柱状图切换或导出功能。

### 验收要求

- 不打开管理页面，普通和流式 API 用量入库后也能触发记录。
- 30 秒内跳过重复 API 触发，下一次统计包含期间累计用量。
- 无使用不建档，同周期重复触发不重复建档。
- 比例为 0%、5% 时预测为空，超过 5% 才计算；最新结果直接覆盖。
- 50% 到 47% 切周期，50% 到 48% 不切周期；自然到期低比例也能切换。
- 新周期金额不混入统计起点之前的日志。
- 合成到期零值、重复快照不导致错误切换；5h 更新不影响周记录。
- API 记录入口不增加上游请求；用量入库失败不触发保存，保存失败不改变原请求结果。
- 列表预测值直接来自当前周期记录，非零显示在用量窗口最下方；null、0 或没有当前记录时隐藏。
- 列表批量读取预测，无逐行查询和前端预测运算；已有列表缓存及 ETag 不掩盖预测值变化。
- 操作列按钮打开对应账号历史，柱状图两组数值与表内数据一致，不重算、不堆叠。
- 柱体保持窄宽度；横轴每个周期均显示小时精度的开始和结束时间，悬浮详情显示已记录的 Token 量和调用次数。
- 历史分页、进行中周期、同日多周期、预测缺失、空数据、加载失败及切换账号均正确展示。

## 2. 不做的事项

- 不支持 Free、5h 和 Spark 独立额度窗口。
- 不处理其他客户端/部署的使用、停机恢复、使用明细丢失或清理。
- 不回填历史，不补偿未记录周期，不重新结算已结束周期。
- 不拆分跨重置的流式 Token，沿用现有用量日志入库时间归属。
- 不增加独立采样、定时查询、收尾定时器、补偿任务或重试队列。
- 不增加逐请求账本、数据库触发器或复杂重置状态机。
- 不增加二次确认、双基线、区间估计、平均、平滑或取最大预测值。
- 不改用户扣费、账号调度、限流及重置次数消费流程。
- 不改用量明细结构、原有入账计算、日志清理、其他平台和 5h 统计。
- 不让预测结果参与计费、调度、限流或自动重置决策。
- 不在账号列表或历史查询接口中重新计算预测，不新增前端预测算法。

## 3. 必须注意的约束

- **比例来源：** 重置判断使用原始 `codex_7d_used_percent` 及快照时间。本地倒计时到期后合成的显示零值不能作为提前重置依据；重复或更旧快照不能重复切换。
- **记录顺序：** API 触发必须在实际用量入库成功之后，不能在请求开始或仅提交异步任务时执行。
- **节流尾部：** 最后一笔请求若落在 30 秒节流内，记录等待下一次请求或窗口刷新才更新，不保证每次使用后立即保存最终金额。
- **重置误差：** 接受比例规则的误判和漏判，例如 1% 到 0% 的提前重置无法识别，额度扩大导致的明显回落也会被当作重置。
- **时间边界：** 提前重置采用发现时间切分，不追溯实际重置时刻，不重新分摊边界附近的使用。
- **预测波动：** 接受已有金额和比例更新不同步产生的短期波动，不增加配对采样机制。
- **无效数据：** 查询失败、窗口缺失或只有过期缓存时保留现有记录，等待下一次有效触发，不伪造比例或预测。
- **失败隔离：** 保存异常只记录日志，不改变用户请求、扣费结果或原窗口显示；如原流程有上游网络请求，应放在数据库事务外。
- **历史保留：** 已结束记录保留最后保存值，不因后来源日志变化而重算。
- **列表缓存：** 列表响应中的预测值参与缓存或 ETag 更新判定，不能只依据其他账号字段判断列表未变化。
- **图表口径：** 两个系列都表示美元金额，不混入使用百分比；使用量与预测总量并排展示，不能堆叠相加。不同周期作为独立类别，不按等长七天时间轴推算。
