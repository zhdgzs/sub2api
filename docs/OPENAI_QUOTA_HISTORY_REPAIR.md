# OpenAI 额度历史修复

适用于升级预测口径后旧预测柱消失，以及同一上游周窗口被不同额度来源错误切成多个连续周期的历史。它是管理员按需执行的数据修复，不是启动自动迁移，也不查询上游。

## 预览与执行

使用目标数据库连接执行，`ON_ERROR_STOP` 必须启用：

```sh
psql -X -v ON_ERROR_STOP=1 -v apply=false -f scripts/repair-openai-quota-history.sql
# 核对周期起止、合并数量、请求数、金额与预测后执行：
psql -X -v ON_ERROR_STOP=1 -v apply=true -f scripts/repair-openai-quota-history.sql
```

脚本使用事务，默认最终回滚。账号行锁和历史表写锁避免与后台采样交错；等待锁最多 5 秒，单条语句最多 60 秒。大库可在维护窗口执行。脚本要求已应用迁移 243。

## 修复口径

- 仅合并首尾连续且相邻上游重置时刻相差不超过 5 分钟的记录，保留最早记录 ID、起点与最后记录的比例、重置时间及有效新快照。执行前必须结合切分日志确认这是错误碎片；脚本不能仅凭比例区分所有真实提前重置。
- 实际请求数、Token、金额按合并后的 `[started_at, ended_at)` 聚合；当前周期聚合至事务开始时刻。Token 包含输入、输出、缓存创建、缓存读取；金额使用 `COALESCE(account_stats_cost,total_cost) * COALESCE(account_rate_multiplier,1)`。
- 若任意周期的可用明细请求数小于保存请求数总和，整次修复报错退出，不把被清理后的残缺明细覆盖到历史。
- 缺失预测使用保存的采样时间及比例，从完整 7 天窗口明细重新计算，不复制旧 `predicted_quota_usd`，也不使用碎片实际金额推算。已有新格式预测快照保留。
- 补算是基于留存资料的历史重建，不能恢复当时未保存的上游比例变化。过期窗口或非正比例不补算。曾经清理部分明细、但有后续新增请求补足计数的情况不能仅由计数检测，需结合运维记录确认明细保留情况。
- 同步当前账号 `extra.openai_quota_period.started_at`，防止后续正常采样重新从错误碎片起点统计；保留最近观察及采样时间。原始 `usage_logs` 不修改。

## 原始备份与验证

`openai_quota_history_repair_backup.original_row` 保存所有原历史行（包括删除的碎片），`openai_quota_history_state_repair_backup.original_state` 保存账号原周期状态，不包含账号凭据。重复执行保留首次备份。

执行后应核对每账号周期数、实际金额与明细聚合是否一致、新预测快照是否完整、当前周期是否只有一条且状态起点一致，并刷新管理端或用户侧“额度历史”。需要恢复时先停用后台写入，再由管理员根据备份还原；不要直接覆盖正在更新的当前周期。

数据修复不会更新运行中的程序。应先部署周期重置判断修复：比例下降不再单独触发切分；上游重置时间须后移超过 5 分钟且仍在未来，自然到期按原边界切分，未到期时还须比例下降超过 2 个百分点才识别提前重置。缺失或明显倒退的重置时间不会清除或污染已有周周期边界，明确非 7 天的快照也不会进入周历史。周期关闭时重新汇总结束边界之前的用量。部署后再修复历史，否则旧代码可能继续写入错误碎片。
